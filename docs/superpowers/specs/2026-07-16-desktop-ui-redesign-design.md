> 日期：2026-07-16  
> 状态：前端 v3 已落地（单一样式表 + 全页设置 + 按需 Inspector）；后端缺口见 `docs/HANDOVER.md`  
> **As-built 规范（实现为准，可提交）**：[`2026-07-16-desktop-as-built-design-system.md`](./2026-07-16-desktop-as-built-design-system.md)

> 参考：当前主流 Agent 桌面端信息架构——轻量侧栏、对话主路径、访问模式合一、上下文占用指示、按需运维面板

## 1. 背景与目标

### 1.1 现状问题

- 永久三栏（左 260 / 中 / 右 320）挤压对话主路径。
- 视觉密度偏 IDE，与主流 Agent 桌面（轻量侧栏 + 对话优先 + 低噪音控件）差距大。
- 设置入口分散（标题栏 + 侧栏）、图标 emoji 混用、圆角/字号/间距无统一阶梯。
- 访问模式与审批策略、模型与思考强度在 Composer 上表达不够清晰。
- 自定义供应商模型列表、思考强度、Worker 注册表单缺少一致的信息架构。

### 1.2 目标

1. **信息架构**：默认双栏（全高侧栏 + 主内容）；Inspector **按需**打开。
2. **视觉系统**：统一 Design Token（色 / 字 / 圆角 / 间距 / 控件高 / 对齐）。
3. **对话主路径**：悬浮 Composer 卡片；访问模式合一菜单；上下文占用环；运行中终止钮。
4. **设置四项**：常规 · 模型设置 · AgentWorker · 关于（仅此四项主导航）。
5. **可实现性**：字段与现有领域模型对齐，标明「线稿已约定 / 实现需扩展」的边界。

### 1.3 非目标

- 不在本设计中实现业务逻辑或改动 ACP 协议。
- 不引入登录/账号体系（无头像区）。
- 不做完整图标品牌授权包交付（使用与产品内一致的公开 SVG 路径即可）。
- 不规定具体 React 组件拆分 PR 顺序（实现阶段另写 plan）。

### 1.4 成功标准

- 对照线稿五屏（首页 / 对话 / Inspector / 设置 / 深色）无结构性偏差。
- Token 表可直接映射到 CSS 变量；实现后视觉审查通过「第 12 节检查清单」。
- 设置与 Composer 字段语义可被现有/扩展数据模型承载（见第 9 节）。

## 2. 总体布局

### 2.1 应用壳

```
┌──────────────────────────────────────────────────────────┐
│ 侧栏（顶到天） │ 主列（空态 / 对话 / 设置全页）              │
│                │                                         │
│                │                    [Inspector 按需]      │
└──────────────────────────────────────────────────────────┘
```

| 区域      | 宽度 Token           | 行为                                            |
| --------- | -------------------- | ----------------------------------------------- |
| 左栏      | `--sidebar-w: 256px` | **全高**贴窗顶/底；红绿灯在侧栏顶部；设置仅左下 |
| 主列      | `1fr`                | 无永久 titlebar 堆砌；设置页占满主列            |
| Inspector | `--drawer-w: 300px`  | 默认关闭；打开时 `侧栏                          | 主  | 抽屉` |

### 2.2 侧栏结构（自上而下）

1. 红绿灯（macOS 窗口控件占位）
2. Brand：`RA` 标 +「Router」
3. 主操作：新建任务 · 打开项目…（**无** Cmd+N 提示、**无**搜索、**无**分组）
4. 分区标题：「项目」
5. 项目树
   - 项目行：**无选中高亮**（仅分组标题）
   - 会话行：选中用 `--bg-active`；busy / 审批用色点
6. 底栏：仅「设置」入口（**无**头像/登录）

### 2.3 相对 v1 桌面 UI 的变更摘要

| 维度     | v1（现状）                 | v2 线稿目标                          |
| -------- | -------------------------- | ------------------------------------ |
| 骨架     | 永久三栏                   | 双栏 + 按需 Inspector                |
| 空态     | 图标 + 说明                | 问候 + 悬浮 Composer                 |
| Composer | 底栏全宽                   | 居中 elevated 卡片                   |
| 设置     | 模态 + 多入口              | 全页四项导航 + 侧栏左下唯一入口      |
| 图标     | emoji 混用                 | SVG sprite / 品牌路径                |
| 访问控制 | Mode chip + 审批 chip 拆分 | **访问模式**合一菜单（橙：完全访问） |

## 3. Design System（规范）

实现时所有样式优先使用下列 token；禁止同屏混用未登记的字号/圆角/间距散值。

### 3.1 色阶

| Token           | Light                | 用途                                  |
| --------------- | -------------------- | ------------------------------------- |
| `--text-1`      | `#1a1d24`            | 主文案、标题                          |
| `--text-2`      | `#5c6370`            | 次级文案、字段标签                    |
| `--text-3`      | `#8b919c`            | 辅助、时间、hint                      |
| `--bg-sidebar`  | `#f0f1f3`            | 侧栏、设置导航                        |
| `--bg-main`     | `#f7f7f8`            | 主内容底                              |
| `--bg-surface`  | `#ffffff`            | 卡片 / Composer / Inspector 面        |
| `--bg-hover`    | `rgba(20,30,50,.05)` | 悬停                                  |
| `--bg-active`   | `rgba(20,30,50,.09)` | 会话/导航选中                         |
| `--bg-input`    | `#f7f7f8`            | 输入底                                |
| `--border`      | `rgba(20,30,50,.10)` | 默认描边                              |
| `--border-soft` | `rgba(20,30,50,.06)` | 轻描边                                |
| `--blue`        | `#3b6ff5`            | 主操作、tab 指示、选中勾              |
| `--green`       | `#1a9e5c`            | 成功、healthy、running                |
| `--accent`      | `#e8890c`            | **完全访问**、>80% 上下文环、审批强调 |
| `--danger`      | `#e04b4b`            | 终止方块、拒绝                        |

暗色：在根节点覆盖同名 token（见线稿 `.frame.dark`），业务组件不散落硬编码 hex（品牌芯片除外）。

**语义色使用规则**

- 主按钮填充：`--blue`，文案反白。
- 危险操作：描边/文案 `--danger`，默认非实心红底（终止钮除外：圆内红实心方块）。
- 成功/运行：`--green`。
- 访问模式「完全访问」文案与图标：`--accent`（橙色）。

### 3.2 字体

**栈**

- UI：`SF Pro Text` → system-ui → `PingFang SC` / `Microsoft YaHei`
- Mono：`SF Mono` → `JetBrains Mono` → Menlo（路径、model id、思考档位）

| Token          | 尺寸     | 用途                        |
| -------------- | -------- | --------------------------- |
| `--fs-2xs`     | 10.5px   | Badge                       |
| `--fs-xs`      | 11px     | 字段 label、hint、tab、状态 |
| `--fs-sm`      | 12px     | Chip、按钮、列表次级        |
| `--fs-base`    | **13px** | 默认 UI 正文                |
| `--fs-md`      | 14px     | Composer 输入               |
| `--fs-lg`      | 15px     | Brand、供应商标题           |
| `--fs-xl`      | 20px     | 文档页标题                  |
| `--fs-2xl`     | 22px     | 设置页标题                  |
| `--fs-display` | 24px     | 空态问候                    |

字重：400 / 500 / 600 / 700（禁止 550、650 等非标）。  
行高：标题 1.3 · 控件 1.4 · 正文 1.5 · 段落 1.55。  
字距：标题 `-0.02em` · 问候 `-0.03em` · 字段 label `0.02em`。

### 3.3 圆角

| Token      | 值       | 用途                      |
| ---------- | -------- | ------------------------- |
| `--r-xs`   | 4px      | 终止方块、极小标签        |
| `--r-sm`   | 8px      | 品牌芯片、段内圆角        |
| `--r-md`   | **10px** | 输入、chip、列表行、按钮  |
| `--r-lg`   | 14px     | 面板、Worker 卡、窗口     |
| `--r-xl`   | 16px     | Composer、设置大卡        |
| `--r-pill` | 999px    | Badge、开关轨道、发送外圆 |

规则：同一视觉层级只用同一档；禁止 6/7/9/12 等散值混用。

### 3.4 间距（4px 网格）

| Token              | 值                                  |
| ------------------ | ----------------------------------- |
| `--sp-1`…`--sp-10` | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 |

习惯：

- 列表行垂直 gap：`2px`
- 表单字段垂直 gap：`16px`（`--sp-4`）
- label → 控件：`6px`
- 控件 → hint：`6px`（hint **永远在控件下方**）
- 图标与文字：`8px`
- Composer 内 gap：`8px`

### 3.5 控件高度

| Token    | 值   | 用途                               |
| -------- | ---- | ---------------------------------- |
| `--h-sm` | 28px | Chip、次按钮、icon btn、多选 chip  |
| `--h-md` | 32px | 导航行、发送/终止钮                |
| `--h-lg` | 36px | **表单输入 / 下拉 / 分段选择外框** |

### 3.6 对齐规范（强制）

| 控件                 | 文案          | 垂直 | 横向                                           |
| -------------------- | ------------- | ---- | ---------------------------------------------- |
| 文本输入             | 左            | 居中 | 全宽；密码 masked 等宽点                       |
| 下拉                 | 左            | 居中 | 文案左 · **caret 右**；数值类可 `numeric` 居中 |
| 分段选择             | 段内居中      | 居中 | 组件整体在 label 下左对齐                      |
| 多选 chip            | 左（勾+文案） | 居中 | 左起流式                                       |
| 主/次按钮            | 居中          | 居中 | 动作行 **靠右**                                |
| settings-row         | label 左      | 居中 | control **靠右**                               |
| 模型列表行           | 名称左        | 居中 | meta 右 · acts 最右                            |
| Composer `chip.menu` | 文案左        | 居中 | caret 右；`+` 图标居中                         |
| 用户消息「你」       | 右            | —    | 与用户气泡右缘一致                             |

### 3.7 图标

- **禁止** emoji 作功能图标。
- 通用 UI：线性 SVG（stroke 1.75，round cap）。
- 品牌：

| 主体                      | 图形                                             | 芯片色                          |
| ------------------------- | ------------------------------------------------ | ------------------------------- |
| Claude Code               | Simple Icons Claude                              | 陶土底 `#f0e6dc` / 字 `#c96442` |
| Codex                     | OpenAI blossom（与 `provider-icons.tsx` 同路径） | `#10a37f` / 白                  |
| OpenCode                  | 官方 O monogram（brand wordmark 首字）           | `#211e1e` / `#f1ecec`           |
| OpenAI / Anthropic 供应商 | 产品内已有 SVG                                   | 绿 / 陶土 A                     |

## 4. 首页空态

- 居中问候：`我们应该在 {project} 中构建什么？`（项目名可下划线强调）。
- **无**建议小卡片行。
- Composer 居中悬浮（见第 5 节）；顶部 context：`项目` · `分支`（**无**「本地」）。
- 无建议卡后垂直节奏：logo（可选）→ 问候 → Composer，主 gap `20px`。

## 5. 对话与 Composer

### 5.1 消息列

- 容器 `max-width: 800px` 居中。
- **用户与 Leader 共用列宽**：用户气泡右缘 = Leader 内容右缘。
- 用户气泡最大约 85% 宽、右对齐；角色「你」右对齐。
- Leader 内容左对齐、可含 `WorkerRunCard` 与行内审批。
- Chat 标题栏：**无** BUILD 徽章；可保留「运行中」状态与 Inspector 开关。

### 5.2 Composer 结构

```
┌─────────────────────────────────────────────────────────┐
│ [项目] [分支]                                            │
│ 随心输入…                                                │
│ [+] [完全访问 ▾]          [○ctx] [模型 极高 ▾] [↑/■]     │
└─────────────────────────────────────────────────────────┘
```

规则：

- 单卡片 `--r-xl` elevated；**上下文行与输入之间无分割线**。
- 圆角与内边距全站 Composer 一致（空态 / dock 仅宽度可不同）。

### 5.3 访问模式（模式 × 审批合一）

单一下拉，替代「Mode chip + 审批 chip」拆分。文案与含义（产品映射见 9.2）：

| 选项         | 说明（UI 副文案）             |
| ------------ | ----------------------------- |
| 变更前确认   | 改文件前先问我                |
| 自动编辑     | 自动编辑文件                  |
| 计划模式     | 编辑前先出计划                |
| **完全访问** | 减少确认次数（**橙色** chip） |

选中项用勾号；菜单圆角 `--r-lg`，项高与 form 多选节奏一致。

### 5.4 上下文占用环

- 位置：模型 chip **左侧**。
- 尺寸：**20×20**；中间 **无 icon**。
- 颜色：默认浅灰进度；**超过 80%** 用浅橙（仍克制）。
- Tip：标题「背景信息窗口」+ `xx% 已用` + `已用 {used} 标记，共 {total}`。

### 5.5 模型菜单

- 展示：`{model short} {思考档} ▾`（如 `5.6 Sol 极高`）。
- 菜单项：
  - 模型 → 级联列表
  - 推理强度 → 级联（轻度 / 中 / 高 / 极高 / 最高…）
- **不包含**「速度」「高级」。

### 5.6 发送 / 终止

| 状态   | 控件                                         |
| ------ | -------------------------------------------- |
| 空闲   | 深色圆钮 + 上箭头 SVG                        |
| 运行中 | 浅底圆 + 描边；中间 **红色实心方块**（终止） |

## 6. Inspector

- 外层：sidebar 底色 + 内边距 8px + 圆角 `--r-lg`。
- 内层 `drawer-panel`：surface **一整块**；Tabs 与 body **同底色连续**。
- Tab 激活：底部 2px 蓝指示条（非悬空白块）。
- Tabs：Workers · Jobs · Git · Files · 审批（与现 RightPanel 能力对齐，可裁剪实现顺序）。
- 审批主路径仍在 **对话内 Worker 卡片**；Inspector 为运维/总览。

## 7. 设置页

### 7.1 信息架构

全页替换主列（非小模态为主路径）。左导航 **仅四项**：

| 导航        | 内容                               |
| ----------- | ---------------------------------- |
| 常规        | 外观、语言、Leader 最大步骤        |
| 模型设置    | 内置/自定义供应商 · 模型列表 · Key |
| AgentWorker | 已注册 CLI · 注册表单 · 侦测       |
| 关于        | 产品名、版本、说明                 |

顶部：「← 返回工作区」。  
**设置入口唯一**：侧栏左下（无右上齿轮重复）。

### 7.2 常规

`settings-row`：左 label+副文案，右控件（下拉 36px，caret 右）。

- 外观：跟随系统 / 浅色 / 深色
- 语言：简体中文 / EN
- Leader 最大步骤：数值下拉或输入（默认 500，范围实现仍遵 10–1000）

### 7.3 模型设置

#### 布局

- 左轨：内置供应商 + 自定义供应商 +「添加供应商」
- 右详情：头栏 + 字段 + 模型列表

#### 头栏

- 供应商名 + logo
- **已启用** tag + **开关**（可切换）
- **保存** 按钮（靠右；**无**「API Key ▾」伪选择）

#### 字段序（自定义供应商）

1. **名称**
2. **接口类型**：OpenAI 兼容 / Anthropic / Google（分段）
3. **Base URL**
4. **API Key**（masked）
5. **模型列表**

Hint 一律在对应控件**下方**。

#### 模型列表（每模型独立）

列表行：模型 id · 上下文简写 chip · 思考档位 tag · 编辑/删除。

展开编辑字段序：

1. **模型 id**（无「显示名称」字段；列表以 id 展示）
2. **上下文窗口**
   - 支持整数或简写：`20K`、`128K`、`1M` 等
   - **无** 20K/128K/1M 快捷 chip 行
3. **支持的思考强度**（本模型 multi-select）
   - 档位：`off` · `low` · `medium` · `high` · `xhigh` · `max`
   - 选项在上，**hint 在最下**：  
     「仅本模型：勾选 …；聊天栏选中该模型时只显示已勾选档位。」

> **实现注**：当前代码 `thinkingIntensities` 在供应商级（`CustomProvider`）。线稿约定为 **per-model**。落地时需扩展模型结构（见 9.1），或先做 UI 折叠再改数据层。

### 7.4 AgentWorker

#### 已注册列表

- 品牌 logo · 名称 · healthy 等状态
- 命令摘要（CLI 路径/参数缩略）
- 角色 pill（★ = 主角色）
- 启用开关
- 工具：自动侦测 · 注册 Worker

#### 注册 CLI Worker 表单

| 字段            | 类型      | 说明                                    |
| --------------- | --------- | --------------------------------------- |
| Worker 名称     | 输入      | 列表显示名                              |
| CLI 路径 / 命令 | mono 输入 | 可执行路径或 PATH 命令                  |
| 启动参数        | mono 输入 | 空格分隔                                |
| 主角色          | 下拉      | 规划 / 编码 / 审查 / 测试 / 调研 / 通用 |
| 可兼角色        | 多选 chip | 须包含主角色；★ 标主角色                |
| 启用            | 开关      | 注册后是否参与委派                      |
| 取消 / 保存     | 按钮      | 动作行靠右                              |

对齐现有 `onRegisterWorker` 载荷：`name`、`command`、`args[]`、`primaryRole`、`roles`、`kind: custom`、`enabled`。

### 7.5 关于

产品名、版本号、简短说明（无营销堆砌）。

## 8. 交互与状态

### 8.1 会话状态点

| 状态   | 侧栏点色   |
| ------ | ---------- |
| 空闲   | 无点或空心 |
| 运行中 | 绿         |
| 待审批 | 橙         |

### 8.2 Worker 卡片（对话内）

- 头：logo · 名称 · 角色 · status
- 体：mono 日志/权限摘要
- 待审批：允许一次 / 始终允许 / 拒绝

### 8.3 深色模式

- 结构不变，仅 token 覆盖。
- 发送钮可用品牌蓝；终止钮保持红方块可读。
- OpenCode 芯片在深色下可反相（浅底深标），保证对比度。

## 9. 数据模型与实现对齐

### 9.1 需扩展（相对当前代码）

| 约定           | 当前                                          | 目标                                                         |
| -------------- | --------------------------------------------- | ------------------------------------------------------------ |
| 模型思考强度   | 供应商级 `CustomProvider.thinkingIntensities` | **per-model** `models[].thinkingIntensities`                 |
| 思考档位       | off/low/medium/high/max                       | 增加 **xhigh**（与线稿一致；实现时扩展 `ThinkingIntensity`） |
| 上下文窗口输入 | 多为数字                                      | 解析 `20K`/`1M` 简写并规范化存储                             |
| 设置壳         | 模态多 tab                                    | 全页四项；入口唯一                                           |

### 9.2 访问模式映射（建议）

| UI         | Leader mode      | 审批策略倾向                                                 |
| ---------- | ---------------- | ------------------------------------------------------------ |
| 变更前确认 | build/ask 视实现 | manual                                                       |
| 自动编辑   | build            | allowAlways（写操作策略内）                                  |
| 计划模式   | plan             | 偏保守 / manual                                              |
| 完全访问   | build            | 更宽的 auto-allow（仍禁止静默危险 delete 等，遵现有 policy） |

具体 ToolKind 矩阵以实现阶段 `permission-policy` 为准，本设计只定 UI 信息架构。

### 9.3 可直接对齐

- `apiStyle`: `openai` \| `anthropic` \| `google`
- Worker 角色：`plan` \| `coder` \| `review` \| `test` \| `research` \| `general`
- 注册字段：`name` / `command` / `args` / `primaryRole` / `roles`
- Leader 最大步骤：10–1000
